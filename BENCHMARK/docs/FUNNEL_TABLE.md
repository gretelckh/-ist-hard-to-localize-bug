## Prose (for the Data Collection / Sampling section)

To build a real, non-fabricated benchmark we mined the entire issue tracker of the official `modelcontextprotocol/python-sdk` and recovered 1343 pure issues (pull requests excluded). A keyword screen labelled 439 of them as candidate bugs; a manual review confirmed 398 genuine bugs (rejecting 41 non-bugs). Of these, 56 already behave correctly on the pinned SDK version (mcp 2.2.0) and were removed, leaving an active dataset of 342 real bugs. We reproduced 49 of them over the production Streamable HTTP transport, each bound to a real issue number. The remaining 293 could not be reproduced at runtime and are classified by the reason recorded during reproduction (see the category table below).

### Why-not-reproducible prose

Of the 342 active real bugs, 49 were reproduced at runtime and form the evidence-based tier-B analysis. The remaining 293 could not be reproduced over the production Streamable HTTP transport. The dominant reasons are environment / transport configuration (106, 36%) --- e.g. stdio/SSE-only cases, platform- or dependency-specific builds, and official example code paths; authentication-limited (48, 16%) requiring OAuth credentials; and cases whose defect is not exercised by a single clean tool call (88, 30%), such as concurrency races, cross-server state, or client-side observation. A smaller set is purely observational or scenario-specific (41, 14%), or reflects a protocol specification gap (6) or an external tool / inspector dependency (4). We report each of these honestly rather than asserting the bug is fixed, and we never fabricate a channel for a bug we could not reproduce.
